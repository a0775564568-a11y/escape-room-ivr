# הסוד של אחוזת בלקווד - חדר בריחה טלפוני

משחק חדר בריחה מלא בעברית, מופעל דרך מערכת IVR של **ימות המשיח**. השחקן מתקשר, נכנס לאחוזה מסתורית, ופותר חידות באמצעות המקלדת של הטלפון. המשחק כולל 12 חדרים, 23 חידות, פריטים לאיסוף, מעברים נסתרים, רמזים וגיבוי אוטומטי של ההתקדמות.

## 1. מבנה הפרויקט

```text
blackwood/
├── api/ivr.js            נקודת הקצה ש-ימות המשיח קוראת לה
├── lib/game.js           חדרים, חידות, פריטים וכל הטקסטים
├── lib/engine.js         מנוע המשחק (לוגיקה טהורה, בדיקה קלה)
├── lib/yemot.js          בניית תגובות לפורמט של ימות המשיח
├── lib/store.js          שמירת התקדמות ב-Hugging Face (קובץ נפרד לכל משחק)
├── scripts/test-game.js  בדיקת פתירות של כל המשחק
├── scripts/generate-effects.js  יצירת אפקטים קוליים (ללא קבצים חיצוניים)
├── scripts/build-docs.js        יצירת VOICE_GUIDE.md ו-AUDIO_FILES.md מהמשחק
├── audio/effects/        קבצי WAV שנוצרו אוטומטית
├── VOICE_GUIDE.md        כל טקסטי הקריינות לפי שמות קבצים, עם הנחיות סגנון
├── AUDIO_FILES.md        רשימת כל קובצי השמע, שמותיהם ומיקומם
├── STORAGE_SETUP.md      הגדרת אחסון, משתני סביבה ושמירת התקדמות
├── vercel.json           הגדרות Vercel
├── package.json          סקריפטים (אין תלויות חיצוניות)
└── .env.example          דוגמה למשתני סביבה
```

## 2. דרישות מוקדמות

- חשבון ב-**ימות המשיח** עם שלוחה שניתן להגדיר בה `type=api`.
- חשבון ב-**GitHub**.
- חשבון ב-**Vercel** (חינמי מספיק).
- חשבון ב-**Hugging Face** עם מאגר Dataset פרטי לשמירת ההתקדמות, וטוקן עם הרשאת כתיבה. ראו `STORAGE_SETUP.md`.
- **Node.js 18 ומעלה** לבדיקה מקומית (אופציונלי).

המשחק אינו דורש שום חבילה חיצונית, כך שאין צורך ב-`npm install`.

## 3. הרצה מקומית ובדיקה

פתחו טרמינל בתיקיית הפרויקט והריצו:

```text
npm test
```

אמורה להופיע הודעה ש-12 החדרים נפתרים בסדר ושהמשחק מסתיים בהצלחה. זו בדיקה אוטומטית שמריצה את כל המשחק עם התשובות הנכונות. אם הבדיקה נכשלת, אל תעלו את המשחק.

ליצירת האפקטים הקוליים מחדש:
```text
npm run effects
```

לעדכון `VOICE_GUIDE.md` ו-`AUDIO_FILES.md` לאחר שינוי בטקסטים:
```text
npm run docs
```

## 4. העלאה ל-GitHub

1. היכנסו ל-[github.com](https://github.com) ולחצו על **New repository**.
2. בחרו שם, למשל `blackwood-ivr`, ובחרו **Private** אם לא רוצים שהקוד יהיה ציבורי.
3. אל תסמנו "Add a README" (הקובץ כבר קיים).
4. אחרי יצירת המאגר, העלו את תוכן הפרויקט:
   - דרך הכפתור **Add file > Upload files**, גררו את כל הקבצים והתיקיות, ולחצו **Commit changes**.
   - או דרך שורת הפקודה:
     ```text
     git init
     git add .
     git commit -m "גרסה ראשונה"
     git branch -M main
     git remote add origin https://github.com/YOUR-USER/blackwood-ivr.git
     git push -u origin main
     ```

**חשוב:** ודאו שאין קובץ `.env.local` עם מפתחות לפני ההעלאה. הקובץ `.gitignore` כבר מונע זאת, אבל כדאי לבדוק.

## 5. חיבור GitHub ל-Vercel

1. היכנסו ל-[vercel.com](https://vercel.com) ולחצו על **Add New > Project**.
2. בחרו את המאגר `blackwood-ivr` מתוך רשימת המאגרים שלכם. אם לא מופיע, לחצו על **Adjust GitHub App Permissions** ואשרו גישה למאגר.
3. בשלב ההגדרה (**Configure Project**):
   - **Framework Preset:** בחרו **Other**.
   - **Root Directory:** השאירו ריק.
   - לא צריך Build Command ולא Output Directory.
4. לפני שלוחצים **Deploy**, פתחו את **Environment Variables** והוסיפו את המשתנים מ-`STORAGE_SETUP.md`:
   - `HF_TOKEN`
   - `HF_DATASET`
   - `IVR_SECRET`
   - `AUDIO_MODE` (אופציונלי)
5. לחצו **Deploy**.
6. לאחר ההפעלה תקבלו כתובת מסוג `https://blackwood-ivr.vercel.app`.

בדיקה ראשונית: פתחו בדפדפן את `https://YOUR-PROJECT.vercel.app/api/ivr?k=הסוד_שלכם`. אמורה להופיע שורה שמתחילה ב-`read=`.

## 6. הגדרת המודול בימות המשיח

1. היכנסו לפאנל ימות המשיח.
2. צרו שלוחה חדשה, למשל בשם `blackwood`, או השתמשו בשלוחה קיימת שרוצים להפוך למשחק.
3. בשלוחה, הגדירו את ההגדרות הבאות (בשורה נפרדת לכל אחת):

```text
type=api
api_link=https://YOUR-PROJECT.vercel.app/api/ivr?k=הסוד_שלכם
```

4. **אל תגדירו טוקן** בשום מקום. השרת לא דורש טוקן של ימות המשיח.
5. ברירת המחדל לשליחת הנתונים היא GET, וזה מה שהמשחק מצפה לו. אין צורך ב-`api_url_post`.
6. לשלוחה לא לשייך הגדרות נוספות אלא אם יש צורך מיוחד.
7. ניתן לשמור את השלוחה ולבדוק.

8. מומלץ להוסיף גם `api_wait_answer_music_on_hold=yes`, כדי שהמתקשר ישמע מוזיקה בזמן שהשמירה ל-Hugging Face מתבצעת.

8. מומלץ להוסיף גם `api_wait_answer_music_on_hold=yes`, כדי שהמתקשר ישמע מוזיקה בזמן שהשמירה ל-Hugging Face מתבצעת.

**הערה:** במשחק הפעילות מתבצעת דרך מודול ה-API. לכן מצד ימות המשיח אין צורך בהגדרות נוספות חוץ מ-`type` ו-`api_link`.

## 7. בדיקת הגדרות בטלפון

לפני פתיחת המשחק לציבור, בצעו בדיקה אחת לפחות מטלפון אמיתי:

1. התקשרו למספר המחובר לשלוחה.
2. ודאו שנשמעת ההודעה הפותחת (הברכה והתפריט הראשי).
3. הקישו `2` (משחק חדש). ודאו שנפתחת מפת החדרים.
4. הקישו `1` ואז `#` (נכנסים למפה), ואז `1` ואז `#`. ודאו שנפתח חדר 1 עם החידה הראשונה.
5. הקישו תשובה שגויה ואז `#`. ודאו שנשמעת הודעת שגיאה.
6. הקישו `99` ואז `#`. ודאו שנשמע רמז.
7. הקישו `15` ואז `#`. ודאו שנשמעת הודעה על תשובה נכונה והתקדמות.
8. הקישו `*` כדי לוודא שחוזרים למפה או לתפריט.

**חשוב ביותר: סדר השדות בתגובת `read`.** המשחק בונה את פקודת `read` בפורמט הבא:
```text
read=t-טקסט=in,,1,4,Digits,no
```
התיעוד הציבורי של ימות המשיח לפקודה `read` בדף הפורום `post/78283` מציג דוגמאות שמתאימות לפורמט זה, אך מומלץ לאמת את משמעות כל שדה מול הדף הנוכחי לפני פרסום. אם הקלט לא מתקבל כראוי בבדיקת הטלפון, פתחו את `lib/yemot.js` ותקנו את הפונקציה `readAction`.

## 8. הפעלת המשחק

1. ודאו שהבדיקה בסעיף 7 עברה.
2. קבעו את מספר הטלפון שיפנה לשלוחה במערכת ימות המשיח.
3. אם אתם משתמשים במצב `file`, ודאו שכל קובצי השמע הועלו לפי `AUDIO_FILES.md`.
4. פרסמו את המספר לשחקנים.

## 9. איך משחקים

- **תפריט ראשי:** `1` להמשך משחק שמור, `2` למשחק חדש, `3` להוראות.
- **חידה:** הקלידו את התשובה ואז `#`.
- **רמז:** הקישו `99` ואז `#`. לאחר שלוש טעויות נשמע רמז אוטומטית.
- **מפה:** הקישו את מספר החדר ואז `#`. מוצגים רק חדרים זמינים.
- **חזרה לתפריט:** הקישו `*` (בתוך חידה או במפה).

כל חדר נפתח רק אחרי שמילאתם את התנאים שלו: פריטים שנאספו בחדרים קודמים. לכן כדאי לחזור לחדרים שכבר פתחתם ולבדוק מה נפתח.

## 10. פתרון תקלות

| מה רואים | סיבה אפשרית | מה לעשות |
|---|---|---|
| "אירעה תקלה זמנית" | שגיאה בשמירה או ברשת | ודאו שמשתני HF_TOKEN ו-HF_DATASET נכונים, ושלטוקן יש הרשאת כתיבה. בדקו את ה-Logs ב-Vercel |
| השרת לא עונה, או "אין מענה משרת API" | כתובת שגויה או שהשרת נופל | בדקו את `api_link` ואת הפריסה בדפדפן |
| אין קול, או שהמשחק מדלג | הקבצים לא הועלו במצב `file` | העלו את הקבצים לפי `AUDIO_FILES.md`, או עברו ל-`tts` |
| הקשות לא מתקבלות | פורמט `read` לא מאומת | ראו סעיף 7 ו-`lib/yemot.js` |
| קוד 403 בדפדפן | `IVR_SECRET` לא תואם | ודאו שהערך ב-Vercel זהה לערך ב-`api_link` |
| התקדמות נעלמת | לא הוגדרו HF_TOKEN ו-HF_DATASET, או שנבחר "משחק חדש" | הגדירו לפי `STORAGE_SETUP.md` |

לפני כל שינוי בפרודקשן, כדאי לשמור גרסה קודמת של הפרויקט (Git) ולבדוק בשיחת ניסיון.
